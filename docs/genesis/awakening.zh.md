# Genesis 首次唤醒

[English](awakening.md) | 中文

本教程通过现有 Web 配置启用可选的单一角色体验，需要[记忆流水线](memory.zh.md)和 Genesis 浏览器配套插件。只使用基础层的部署保留原有行为。

## 配置并启动

工作区 Web 启动默认使用 `~/.genesis-harness`；需要其他位置时，显式设置绝对路径 `DSH_HOME`。延续同一生命时，后续启动和不同配置须沿用相同主目录与存储根目录，不要让两个进程同时写入。

按照[运行说明](README.zh.md)构建后启动。嵌入服务环境变量可暂时留空，启动后在浏览器中配置：

```sh
pnpm dsh web
```

工作区启动层会补齐三个 Genesis 覆盖配置，默认端口为 4004，可用 `--port` 显式覆盖。为已有但尚未命名的生命重启时，保留相同的 `DSH_HOME` 和存储配置，不要通过删除生命数据触发命名。需要不带这些默认配置的普通 Harness 时，参见[运行说明](README.zh.md)。

先通过现有模型/API 配置或账号登录界面配置对话，再按照[记忆配置说明](memory.zh.md)在“设置 → 知识库”配置决策模型、记忆更新模型和嵌入服务。生命覆盖配置默认使用 `deepseek-official` / `deepseek-v4-flash` 对话与写入，使用 `https://api.typesafe.ai/v1/systemone` 上的 TypeSafe `jev-latest` 决策。`GENESIS_CHAT_PROVIDER` / `GENESIS_CHAT_MODEL`、`GENESIS_DECISION_URL` / `GENESIS_DECISION_MODEL`、`GENESIS_WRITER_PROVIDER` / `GENESIS_WRITER_MODEL` 提供部署默认值。通过知识库或环境变量保存 `GENESIS_DECISION_API_KEY`；图形配置优先，密钥不进入生命历史。

配置提醒提供“不再出现”，通过主机设置保存为 `ui-settings-general.credentialOnboardingDismissed`，刷新和重启后仍生效，不关闭手动模型设置。命名不自动弹出：请在新对话界面、“生命信息”或“知识库”点击“初始化生命”，配置就绪后由按钮打开命名表单。保存时探测嵌入服务并为已有身份命名。检查失败保留名字，存储或备份错误须先检查两份数据再重试。冲突的再次初始化不能重命名或替换生命。

## 与她相识

主动点击初始化后，保存名字会创建并打开生命模式对话，触发她先打招呼。内置提示以 `genesis-awakening` 来源写入日志，不冒充用户介绍。她起初知道已记录的名字和诞生信息、基本语言及温柔的人设指导，不知道用户个人事实，也没有共同经历。你可以持续多轮介绍自己并教她。已命名但尚未完成首次对话的生命保留“进入第一次对话”入口，只有首次会话成功完成一条文字回复后按钮才消失，完成状态与原身份都会跨重启保存。

回复后，独立评审模型判断哪些信息值得保留；另一个写入模型校验来源，将记忆、嵌入及本地备份一并保存。对话模型不能保证未经评审的自我介绍已经保存。刷新“设置 → 记忆”即可查看和管理产生的记忆。成本、输入限制、错误和恢复方式见[记忆说明](memory.zh.md)。

## 教她学习工具

生命模式是第五个可选预设，也是部署中新对话的默认模式。标准、PTC、极简和创造模式保持原 Harness 任务行为和独立对话上下文，不附带生命身份、情绪或记忆更新。只有生命模式使用初生角色提示词和学习限制；初始工具为 `learn`（学习）和 `genesis_recall`（回忆），回忆可使用近似主题或相关词，无需显式学习。其他工具通过 `learn` 每次学习一个准确名称，不提供目录；学习成功后，该工具加入后续生命模式请求。

学习记录在不同会话和重启之间共享。被移除或受到会话作用域限制的工具仍有学习记录，但恢复可用之前无法调用。未知名称会被拒绝，不会透露其他选项。即使调用者伪造名称或绕过提示词组装，执行器上的单调拒绝检查也会阻止未学习的工具；学习之后仍须通过独立的沙箱和审批策略。学习不安装插件，也不授予权限。

## 个人目录

生命覆盖配置创建私有目录 `$DSH_HOME/personal`，通常为 `~/.genesis-harness/personal`。路径与文件在当前主机上跨对话、工作区及重启保留。她学会 `read` 和 `write` 后，已记录的生命上下文会告知该路径；`workspace-write` 策略将其与当前工作区一起授权。仍须使用当前确实可用的工具，学习不会绕过只读模式或操作者控制。

`personalDirectory` 可指定绝对且非根目录的路径。现有目录必须归当前身份所有、保持私有且不是符号链接。路径一旦被记录，目录缺失或变化会拒绝启动；应恢复原文件，不会悄悄重建空目录。个人文件须独立于生命 JSON 备份保存。Genesis 卸载后，后续策略解析移除额外授权；已运行的受限进程保留启动时权限，直到退出。

## 上下文与恢复

短时上下文只属于当前会话。新建无关的生命模式会话会共享生命 ID、名字、已学工具和长期记忆，不会复制旧消息、工具结果或辅助记忆调用日志。陈述性知识需要主动进行嵌入回忆检索，受限的非陈述性记忆层和相关记忆线索进入已记录上下文，详细来源及以往认识仍可通过回忆获取。恢复同一会话则会有意恢复该会话自身的上下文。

生命模式选择角色提示词，并省略可能透露未学工具名称的可选运行时上下文，必须使用原生工具展示。其余模式保留自身提示词与工具展示方式，包括 PTC；排除生命上下文与工具，其交流不更新生命记忆、情绪、兴趣或能力历史。所有模式继续遵守正常执行策略。已学习能力体现为工具使用和记忆，不代表训练模型权重、自主目标或主动唤醒调度。生命覆盖配置同时启用独立[情绪评估](emotion.zh.md)。

插件启动时会持久预留身份，命名标志首次唤醒。命名不改变诞生时间或生命 ID。首次会话和学习事件是持久且幂等的生命事实，与对话上下文分开。工作区启动时使用前置 `--no-genesis` 可关闭默认 Genesis 行为，显式组合的配置也可移除生命覆盖配置；这些操作不删除生命；恢复时须沿用同一存储、备份和租约。不要通过删除身份数据来重复命名流程。
