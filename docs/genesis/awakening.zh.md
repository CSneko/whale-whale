# Genesis 首次唤醒

[English](awakening.md) | 中文

本教程通过现有 Web 配置启用可选的单一角色体验，需要[记忆流水线](memory.zh.md)、已配置的嵌入端点和 Genesis 浏览器配套插件。只使用基础层的部署保留原有行为。

## 配置并启动

为本项目使用一个专用的绝对路径 `DSH_HOME`，后续启动和不同配置都沿用它。其 `genesis` 存储域只拥有一个生命，无关会话不会产生新生命。延续同一生命时不要更换主目录或存储根目录，也不要让两个进程同时写入。

在本地启动环境中配置 `GENESIS_EMBEDDING_URL`（包含 `/embeddings`）、`GENESIS_EMBEDDING_MODEL`、`GENESIS_EMBEDDING_DIMENSIONS` 和密钥 `GENESIS_EMBEDDING_API_KEY`，与记忆覆盖配置使用同一组嵌入设置。使用无密钥本地嵌入服务时，在自己的补丁中移除 `embeddingKeyEnv`。按照[运行说明](README.zh.md)构建后启动：

```sh
pnpm dsh web --patch packages/experimental/genesis/cordis.patch.yml --patch packages/experimental/genesis/cordis.life.patch.yml --patch packages/experimental/client-ui-genesis/cordis.patch.yml
```

先使用现有的模型/API 配置或账号登录界面。提供的覆盖配置对主对话和独立记忆调用默认使用 `deepseek-official` / `deepseek-v4-flash`。可通过 `GENESIS_CHAT_PROVIDER` 和 `GENESIS_CHAT_MODEL` 选择其他已注册路由，并通过 `GENESIS_DECISION_PROVIDER`、`GENESIS_DECISION_MODEL`、`GENESIS_WRITER_PROVIDER`、`GENESIS_WRITER_MODEL` 分别覆盖辅助路由。三条路由都须成功准备才能命名。服务配置和登录仍由现有 Harness 服务管理，Genesis 不保存账号凭据。

配置完成后，命名对话框会请你为她取名。保存时会用一次小型探测检查嵌入端点，再为已预留的身份命名。检查失败会保留表单以便重试。可以从对话框返回模型设置；准备好重试时，可在“通用 → Genesis”中使用相同命名表单和刷新操作。存储或备份报错可能发生在写入已经提交之后，重试前须检查两份数据。第二次初始化若使用不同名字，会拒绝重命名或替换生命。

## 与她相识

命名成功后对话框关闭。在对话输入框发送第一条真实消息，介绍自己、描述偏好并和她交流。内置提示词将她设为好奇、懵懂天真、温暖可爱的年轻女性角色，不编造用户信息或共同经历。为已有生命开启唤醒功能时，原有记忆会完整保留。同一基础人设和选出的非陈述性记忆会伴随后续会话，不会每次新建会话都重新变成新生儿。

回复后，独立评审模型判断哪些信息值得保留；另一个写入模型校验来源，将记忆、嵌入及本地备份一并保存。对话模型不能保证未经评审的自我介绍已经保存。刷新“通用 → Genesis”即可检查产生的记忆预览。成本、输入限制、错误和恢复方式见[记忆说明](memory.zh.md)。

## 教她学习工具

最初唯一向模型开放的工具是 `learn`，展示为“学习”。唯一参数是一个准确的工具名称；工具描述不提供清单、枚举或名称示例。请明确告诉她工具名，例如：“请学习 genesis_recall，以后需要回忆时可以使用它。”学习成功后，该工具的声明会加入下一次请求。学习一个工具不会解锁其他工具。

学习记录在不同会话和重启之间共享。被移除或受到会话作用域限制的工具仍有学习记录，但恢复可用之前无法调用。未知名称会被拒绝，不会透露其他选项。即使调用者伪造名称或绕过提示词组装，执行器上的单调拒绝检查也会阻止未学习的工具；学习之后仍须通过独立的沙箱和审批策略。学习不安装插件，也不授予权限。

## 上下文与恢复

短时上下文只属于当前会话。新建无关会话会共享生命 ID、名字、已学工具和长期记忆，不会复制旧消息、工具结果或辅助记忆调用日志。陈述性知识需要已学习的搜索工具进行嵌入检索，只有受限的非陈述性记忆层会自动进入上下文。恢复同一会话则会有意恢复该会话自身的上下文。

唤醒模式选择完整的角色提示词，替换默认的编程助手段落及可能泄露未学工具名称的可选运行时上下文。必须使用原生工具展示方式；PTC 组合会显式失败。正常的会话提示词/工具日志以及执行策略继续生效。当前层不提供自主目标、情绪或主动唤醒调度。

插件启动时会持久预留身份，命名标志首次唤醒。命名不改变诞生时间或生命 ID。首次会话和学习事件是持久且幂等的生命事实，与对话上下文分开。移除生命覆盖配置会关闭这部分行为，但不删除生命；恢复时须沿用同一存储、备份和租约。不要通过删除身份数据来重复命名流程。
