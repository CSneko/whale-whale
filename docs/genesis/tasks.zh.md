# Life 与工作区任务

[English](tasks.md) | 中文

## 模式

工作区 Genesis Web 组合将 Life 设为新会话的默认模式。Life 会话共享一个身份、情绪状态、长期记忆和已学工具，同时保留独立上下文。标准、PTC、极简和创造会话使用原 Harness 行为，不接收生命上下文或工具，不产生生命观察，不运行记忆、情绪、兴趣评审，也不进入生命能力历史。经过认证的逐回复记忆操作仅在参与生命模式的会话中可用。

隔离由 `awakening.lifePreset` 控制。未启用 awakening 的基础组合，或未限制预设的 awakening，保留所有会话参与的策略。已有普通会话的历史可能已经包含生命上下文；需要干净任务时请新建普通会话。原有生命存储和会话日志均保留。

## 安排工作

使用带 Life 与浏览器覆盖配置的[工作区启动方式](README.zh.md)。任务工具要求通过 `awakening.lifePreset` 指定独立生命预设；工作区注册表、预设注册表、默认模型、会话持久化及会话查询服务均挂载后，任务工具才可用。普通 Web 组合提供这些服务。通过现有模型设置配置实际可用的任务默认模型。

与其他[已学工具](awakening.zh.md)一样，通过 `learn` 教授 `genesis_tasks`。它不出现在初生工具列表中，学习不授予执行权限。学会后，AI 可以使用这些操作：

| 操作 | 输入与结果 |
| --- | --- |
| `catalog` | 返回已注册工作区的 ID、路径、名称，以及普通模式 ID 和可用性诊断。`default_mode` 可以是 Life；创建任务仍必须明确指定普通模式。 |
| `create` | 必须提供 `workspace_id`、`mode`、`request_id` 和独立完整的 `prompt`。返回 `task_id`、目标工作区和模式，以及提交状态。 |
| `list` | 必须提供 `workspace_id`；返回会话/任务 ID、模式和是否存在运行实例。`not-loaded` 不代表完成；请使用 `inspect`。 |
| `inspect` | 必须提供 `task_id`；返回实际任务状态、Life 分配任务时的请求来源、最近一轮助手文本和已记录的失败信息，不唤醒或重试任务。 |

`offset` 和 `limit` 在 `queryLimit` 内分页读取目录或列表。检查使用字符 `offset`、`result_chars` 和 `next_offset`；`resultChars` 限制完整响应，超限会明确失败。`result_complete` 表示最近一轮已完成，`next_offset` 表示仍有文本可读。运行中或失败的轮次可以包含部分文本。

每次分配都会在目标工作区创建不继承历史的普通会话，只传递明确提供的提示词，不复制对话、生命快照或记忆。任务模式不会默认回到 Life。提交保留调用方沙箱模式与部署默认值中更严格的限制，并保留拒绝审批请求的策略。既有工具策略、审批和操作者停止控制仍然适用。任务独立于发起会话，结束发起会话不会取消其工作。

重试相同工作时复用同一个 `request_id`。该标识属于单一生命，跨会话与重启有效；并发或后续重试返回既有任务，不重复提交。使用相同标识提交不同输入、工作区/模式不可用或预留记录不完整时，会明确失败。运行实例丢失后会报告中断；检查不会宣称执行成功或自动重跑。此工具立即分配工作，不新增按时间触发的调度器。

## 人工查看

打开目标工作区的正常会话列表即可找到新会话，原有模式标签、对话历史和运行控制均保留。分配内容以带来源的 Life 通知出现，后续展示真实助手和工具输出。任务 ID 就是会话 ID，分配来源保留发起 Life 会话和请求标识。`inspect` 也能读取已注册且未归档工作区中的既有普通会话，拒绝 Life 会话及该集合以外的会话。

任务输出是带归属的数据，Life 需要自行判断如何使用；输出文本不能授予权限或覆盖操作者指令。完成状态表示工作会话的真实轮次结束结果，不独立证明答案正确。当前测试使用脚本模型验证真实 Loader 组合和持久化，不代表已验证真实模型提供方或桌面/浏览器兼容性。
