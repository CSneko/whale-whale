# Genesis architecture

[English](architecture.md) | 中文

## 概要

实验性 Genesis 插件拥有一个持久生命。生命核心依赖 Storage Domain 接口和数据类型，适配层负责 Cordis、会话证据、提示词贡献与原生工具，不替换 Agent Loop 或模型提供方。

## 加载与所有权

加载时先获取独占写入锁，再打开 `genesis` 域、校验已有记录、恢复身份或将身份和诞生事实原子创建，随后记录启动。域读取失败绝不创建替代身份。所有访问同一数据的进程必须共用锁路径。

核心串行执行读改写操作，每次提交一条完整状态记录。已接受的工作与正常停止事实处理完毕后才关闭存储域。插件 effect 撤销工具、提示词与监听器，卸载时释放锁。崩溃可能不产生停止事实并遗留锁文件。

## Harness 集成

`agent/created` 将真实会话关联到既有生命，`system-prompt/assemble` 和 `agent/pre-step` 刷新选定上下文及真实作用域工具声明。Harness 按原机制记录贡献的系统与运行时上下文，原生工具结果沿既有持久工具流程处理。

`session/event` 将真实用户消息和工具结果记录为元数据事实，使用会话 ID 与序号去重，不向会话重新发布事件。适配层只保留最近用户证据和待完成工具调用名称，不使用已弃用的同步历史会话读取接口。

事实描述实际发生的事情，记忆保存带归属的解释。模型输出不能修改身份；唤醒模式下，经校验的学习调用会记录已学能力，但不授予执行权限。实时可用性属于 Agent 作用域，旧会话观察保持为历史，授权仍由 Harness 执行流程负责。

可选[记忆流水线](memory.zh.md)接入 `agent/turn-stopping`，在不同会话之间串行执行独立审核，并在核心卸载前排空或取消远程工作。辅助调用使用已配置的 Harness 模型适配器，嵌入请求使用显式端点。陈述性回忆由工具触发，只有少量非陈述性记忆进入提示词。核心的每次提交还会替换本地备份。

可选[唤醒层](awakening.zh.md)拥有完整角色提示词、命名前置条件和已学工具声明选择。注册表上的单调拒绝检查会独立阻止未学工具调用。只有已学工具观察会进入自我上下文，因此注册表清单不会成为模型初始输入。首次会话和学习事实存于同一生命域，无关会话不共享对话记录。

## Web 状态

可选浏览器配套插件独立挂载生成的实验性 Remote，不加入稳定 API 汇总。`GenesisStatusGateway.inspect` 通过现有认证 Gateway 采样真实运行工具与有界持久记录预览。常规设置贡献使用共享资源模型，按用户操作或重连刷新，不轮询，也不新增端口。启用唤醒后，认证的 `initialize` 操作准备所配置路由、探测嵌入服务，并一次性提交用户选择的名字。API/账号配置使用既有服务；生命卸载前会取消并排空命名操作。
