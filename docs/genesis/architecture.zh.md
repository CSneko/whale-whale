# Genesis architecture

[English](architecture.md) | 中文

## 概要

实验性 Genesis 插件拥有一个持久生命。生命核心依赖 Storage Domain 接口和数据类型，适配层负责 Cordis、会话证据、提示词贡献与原生工具，不替换 Agent Loop 或模型提供方。

## 加载与所有权

加载时先获取独占写入锁，再打开 `genesis` 域、校验已有记录、恢复身份或将身份和诞生事实原子创建，随后记录启动。域读取失败绝不创建替代身份。所有访问同一数据的进程必须共用锁路径。

核心串行执行读改写操作，每次提交一条完整状态记录。已接受的工作与正常停止事实处理完毕后才关闭存储域。插件 effect 撤销工具、提示词与监听器，卸载时释放锁。崩溃可能不产生停止事实并遗留锁文件。

## Harness 集成

`agent/created` 将参与生命模式的真实会话关联到既有生命，`system-prompt/assemble` 和 `agent/pre-step` 刷新选定上下文及真实作用域工具声明。Harness 按原机制记录贡献的系统与运行时上下文，原生工具结果沿既有持久工具流程处理。

`session/event` 将真实用户消息和工具结果记录为元数据事实，使用会话 ID 与序号去重，不向会话重新发布事件。适配层只保留最近用户证据和待完成工具调用名称，不使用已弃用的同步历史会话读取接口。

事实描述实际发生的事情，记忆保存带归属的解释。模型输出不能修改身份；唤醒模式下，经校验的学习调用会记录已学能力，但不授予执行权限。实时可用性属于 Agent 作用域，旧会话观察保持为历史，授权仍由 Harness 执行流程负责。新生命的成长记录为空。每个会话首次取得的注册表视图合并为一条基线事实，只有该作用域之后的变化和显式学习才产生成长。注册表快照在已学工具过滤之前取得，过滤仅控制角色访问和展示。重复的相同扫描不追加事件，已有持久历史保持完整。

可选[记忆流水线](memory.zh.md)在 `agent/turn-stopping` 中串行处理不同会话的评审。已注册 Harness 适配器或显式 Jev/Chat Completions 端点接收已记录的有界输入，嵌入使用独立端点。评审失败会被隔离并单独报告，不使已完成聊天失败。图形模型和嵌入配置在生命租约下各自使用版本化存储域。可选[情绪评估](emotion.zh.md)拥有独立串行决策与写入流程以及有界可重放对话投影，共享模型路由与原子生命状态所有者。卸载时取消或排空记忆与情绪工作，关闭配置与核心存储，再释放租约。

可选[唤醒层](awakening.zh.md)仅对配置的生命预设应用角色提示词和已学工具限制，只有生命模式会话参与身份、记忆、情感与能力历史；普通预设不进入该生命周期。浏览器通过既有 Session API 创建首次会话，再由生命 Gateway 一次性加入带来源标识的内置问候。轮次投影拒绝非空目标，生命事件在接受问候前记录首次会话标识；独立会话不共享对话上下文。

可选[审议](motivation.zh.md)在 `agent/pre-step` 调用独立写入模型，并把已提交选择作为有来源标记的通知保留在会话日志。实时决策通过单调工具守卫限制任务执行；可信事件入口复用普通 Agent 收件箱继续生命目标。模型不能通过文本完成目标或扩大权限，取消与卸载会排空已接受的审议和结果结算后再关闭存储。

## Web 状态

可选浏览器配套插件独立挂载生成的实验性 Remote，不加入稳定 API 汇总。`GenesisStatusGateway.inspect` 通过现有认证 Gateway 采样真实运行工具与有界持久记录预览。独立的“生命信息”和“知识库”页面使用共享资源模型，按用户操作或重连刷新，不轮询，也不新增端口。启用唤醒后，认证的 `initialize` 操作准备所配置路由、探测嵌入服务，并一次性提交用户选择的名字。API/账号配置使用既有服务；生命卸载前会取消并排空命名操作。
