# Genesis 动机与审议

[English](motivation.md) | 中文

## 概要

可选审议把既有心理需求、带来源兴趣、标明归属的人格记忆与跨 Session 生命目标连接起来。独立写入模型提出选择，生命核心校验引用、数值范围和状态变化；单调工具守卫把行动意愿与执行授权分别落实。

## 启用

工作区 Life 覆盖配置同时启用 `deliberation: {}`、记忆、情绪和兴趣，其他配置可组合可选覆盖文件：

```sh
pnpm dsh --profile headless --patch packages/experimental/genesis/cordis.patch.yml --patch packages/experimental/genesis/cordis.deliberation.patch.yml --dump-config
```

配置转储只验证组合。配置模型路由后，将 `--dump-config` 替换为任务即可交互。审议需要 `memory`，复用已保存的独立写入模型、取消时限、输入输出及 token 限制，不要求单独模型提供方或嵌入。情绪与兴趣仍是独立可选功能；唤醒把角色限制在 Life 预设时，审议只作用于该预设。禁用审议会保留持久记录，并停止选择注入及其意愿守卫。

## 持久状态

| 记录 | 字段与含义 |
|---|---|
| 心理需求 | 复用情绪 `Needs` 中的探索、创造、自主和社交需求；能力成长以实际能力及成长记录为依据。 |
| 兴趣读数 | 既有兴趣 ID、主题、阶段、形成时间和交流证据；强度是排除纯接触后的正向信号占比，休眠时为零，稳定性是自主重访占比。这些读数由持久证据派生，属于解释，不是新事实或技能。 |
| 动机 | 品牌化 ID、具体意愿、标明归属的原因、关联兴趣和记忆及来源事件 ID、强度、active/paused/ended 状态与创建更新时间。 |
| 生命目标 | 品牌化 ID、不可变内容及 autonomous/user/event 来源、原因、动机和记忆及来源链接、优先级、active/paused/completed/abandoned 状态、下一步、失败次数、时间及变化历史。 |
| 决策 | 品牌化 ID、Session 内稳定重放键、触发及来源 ID、候选行动与评估、选择序号、原因摘要、关联目标和动机、时间及实际结果引用。 |

版本 1 的 `agency` 投影以空动机、目标和决策开始，并记录 `agency.initialized` 生命事件。它复用拆分存储、原子提交、独立备份及显式失败恢复。缺少 `agency` 的旧状态仍可读取，旧版严格读取器会拒绝新增字段。参见[升级指南](../upgrade-guide/v0.2.1-rc.2/genesis-deliberation/guide.zh.md)。

动机强度保持在 [0, 1]。每次带来源的修订最多相对衰减后强度移动 `deliberation.maxStrengthDelta`，新动机先从零开始再应用限幅。`motivationHalfLifeMs` 控制相对已记录锚点的指数衰减，包括重启期间经过的时间；暂停和结束的动机不产生当前压力。兴趣沿用交流证据推进，明确负面体验允许休眠，时间流逝和沉默不会抹除偏好。主题与意愿根据经历提出，不随机选择，也不预设喜爱清单。

## 请求决策

普通用户输入获准进入前，`agent/pre-step` 检索有界相关记忆、自我和过程倾向、情绪需求、当前兴趣、未完成目标、近期经历、结果及真实作用域能力。写入模型提出候选行动，并评估动机、兴趣、承诺、情绪、需求、收益、成本、风险、紧迫性、关系与情境。这些数值属于标明归属的估计，不用情绪阈值机械决定拒绝。

最终选择为 `accept`、`negotiate`、`defer`、`decline`、`clarify` 或 `wait`。拒绝或权衡必须关联已记录目标或动机。程序检查不能证明模型解释合理，因此写入模型还被要求避免刻意反抗，并根据新信息重新考虑。原始用户输入保持完整，已提交选择作为 `genesis-deliberation` 通知追加到会话日志。

只有已接受的实时决策允许任务工具。其他选择可以解释、协商或请求协助，即使会话模型忽略通知，执行器仍拒绝工具调用。新用户消息触发新的选择；暂停或放弃关联生命目标会在后续工具调用前撤销既有准入；既有授权、沙箱、预算、工具学习限制和操作者停止控制继续有效。模型计划和通过意愿检查都不授予权限。

## 自主入口与结果

可信事件适配器和未来调度器可读取 `ctx.get('genesisDeliberation')`，缺失表示未启用可选功能。`deliberate(agent, { key, sourceEventId }, signal)` 要求空闲角色 Agent 及既有生命事件，可以继续目标、在无用户任务时提出目标、暂停恢复放弃目标、请求协助或等待。等待不排队执行；其他选择排队一条已记录后续消息，接受执行必须关联 active 生命目标。新目标的空动机链接解析为本次修改的动机，所选行动的空目标链接解析为本次修改且保持 active 的目标。

稳定重放键避免重复推理和派发。排队前原子保留派发资格；崩溃后不会自动重新派发尚未确认的预约，因为消息可能已经进入执行。检查决策与会话日志，再用新事件键发起新的审议。并发状态变化会拒绝过期提案，不覆盖当前目标。

实际助手与工具事件将决策结算为 responded、succeeded、failed 或 interrupted，等待单独记录。成功仅表示观察到成功工具结果，不代表生命目标完成。失败会增加关联目标计数，并进入后续审议证据，允许调整策略。既有兴趣评估也接受已记录自主决策的真实结果，计划本身不足以作为经历证据。重要决策和目标变化追加生命事件，当前状态可跨无关 Session 恢复。

只有可信应用在独立验证关联执行成功后，才调用 `LifeCore.completeLifeGoal(goalId, decisionId, evidenceId)`。核心要求 active 目标、已结算成功决策及其结果中的成功工具事实；审议提案和普通文本不能设置 `completed` 或更改权限。确认完成会记录目标历史与成长事件。生命目标独立于 Harness `ctx.goals`，选定工作使用普通 Agent 收件箱和工具流程，不替换 Session Goal，也不冒称其完成。

## 限制与扩展

`maxMotivations`、`maxGoals`、`memoryLimit`、`memoryChars` 和 `contextChars` 限制清单、检索及当前上下文，其他集合由 `queryLimit` 限制。辅助输入在必要时移除可选条目，完整触发输入过大则拒绝。生命全局记录数与字符限制包含审议记录及历史；容量和校验失败不改变已提交状态，存储写入不确定时停止依赖操作直到验证后重新加载。输入获准前的辅助推理失败会停止该请求，不会默默接受。

当前集成不提供后台唤醒计时器或新图形编辑器。外部事件结果不会自动运行面向用户交流的记忆或情绪写入模型。关键词检索和模型评估可能遗漏相关证据，兴趣数值描述证据比例，不是经科学验证的心理测量。真实模型的决策质量需要部署凭据评估；免密 Loader 测试验证日志、执行拦截、自主派发、兴趣证据及重启连续性。未来调度可调用同一可取消入口，应用专用结果校验器可确认更多目标完成类型，无需把权限管理交给角色状态。
