# Genesis 主动消息

[English](social.md) | 中文

## 配置与状态

打开“设置 → 主动消息”，保存启停开关、可选目标会话 ID、检查周期、最小发送间隔、滚动二十四小时上限、安静间隔、重要记忆阈值、待发送数量上限和机会有效期。编辑器中的时长使用秒，持久化设置与 `socialInitiative` 配置使用毫秒。已保存设置覆盖部署默认值并跨重启保留；过期写入保留草稿，直到显式重新加载。

源码工作区的 Life 覆盖配置以暂停状态加载工作器，在页面中启用后才产生机会。其他配置须明确组合 `socialInitiative`、记忆和审议；未加载时显示不可用，但仍可读取已存历史。原本明确配置 `socialInitiative: {}` 的部署保留默认启用行为。填写目标 ID 不会创建或打开会话；留空时选择最近有真实用户活动的空闲角色会话。一旦开始审议，该机会保留已选会话。

页面显示采样时的运行状态、下次定时检查、最近交流机会、真实在线渠道、计数、最近确认消息及有界机会历史。刷新会重新读取后端，读取失败保留上一份样本；预览截断和省略记录均明确标注。待发送或已排队都不代表投递成功。模型及传输诊断与相关记录一并展示，原始辅助响应留在 Session 审计日志中。暂停会阻止新机会及排队通知准入，已经进入模型的一轮仍可能完成。

## 决策与投递

dsh 运行期间，定时器、目标完成、重要记忆或新自主目标提供一次交流机会。稳定运行时，定时器在检查完成后安排下一次延迟；保存策略会重新安排计时。审议与回执核对串行执行。持久化事件游标避免反复扫描旧触发；启用或暂停时从当前位置开始考虑事件，不重放暂停期间积累的事件；其他设置修改保留尚未处理的事件。既有写入模型结合有界情绪、动机、记忆与关系自主考虑，也可以选择安静；不增加独立社交驱动或固定话术。

选择交流后检查冷却时间、滚动上限、用户安静间隔、机会是否过期及渠道是否可用。通知进入轮次时再次检查限制，真实用户输入优先。渠道缺失或忙碌时保留待发送，过期机会跳过。这些时长使用真实墙钟，与情绪离线计时开关独立；待发送记录、决策归属及成功或不确定的投递时间使限制在重启后仍然有效。

工作器先持久保留派发资格，再排队带 `genesis-initiative` 来源的通知。通知是模型内部上下文，不是操作者输入；普通 Harness 循环以 Genesis 的口吻生成真正的 `assistant/message`。主动轮次不能使用任务工具，也不授予额外权限。只有实际提交的助手回执才能提供消息序号、内容和发送时间，回执投影可从 Session 日志重放。

## 恢复与限制

中断前缀或没有助手回执的已结束轮次标为不确定，可用时保留安全的轮次失败代码。重启后找不到原会话的派发预约也会转为不确定，不再阻塞所有后续机会。不确定记录不自动重发，并计入发送限制；若原 Session 后来恢复且含有效完整回执，可以确认同一次投递，不另生成消息。进一步操作前应检查原会话。

存储或备份结果不确定时，依赖的生命操作会停止。有限待发送队列和全局生命状态预算继续生效，不静默丢弃记录。降级包含新增设置及游标的存储前，参见[升级兼容说明](../upgrade-guide/v0.2.1-rc.2/genesis-proactive-controls/guide.zh.md)。

投递使用运行中且空闲的 Harness 角色会话及已配置模型路由，进程停止期间不会运行。隔离 Loader 测试验证定时与事件机会、安静分支、限制、助手角色、投递失败、回执和重启去重；脚本化模型不能证明生产提供方质量。设置页复用已认证的生成 Remote 服务与共享按需资源，不新增监听端口。
