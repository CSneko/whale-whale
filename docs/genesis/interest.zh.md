# Genesis 兴趣

[English](interest.md) | 中文

## 概要

Genesis 可以从已记录的交流中形成主题兴趣，初始不预设喜欢的领域。兴趣是有归属的行为解释，不等于记忆事实、即时情绪、工具技能或执行权限。

## 启用

工作区生命覆盖配置与记忆、情绪一起启用 `interest: {}`。其他配置可在核心补丁后叠加可选兴趣补丁：

```sh
pnpm dsh --profile headless --patch packages/experimental/genesis/cordis.patch.yml --patch packages/experimental/genesis/cordis.interest.patch.yml --dump-config
```

配置转储只检查组合。实际对话还需配置模型路由；兴趣评估使用已保存的独立记忆写入路由，以及 `memory` 的输入、输出、Token 和超时限制。关闭 `interest` 会停止评估与上下文注入，但保留已有兴趣记录。

## 从经历发展

初始兴趣清单为空。包含真实用户消息与助手回复的一轮交流完成后，独立写入模型调用可提出最多两个主题变化，也可以不改变。输入包含有界的近期对话以及工具名称和成功结果；工具参数和结果正文仍留在 Session 日志。接触、好奇、探索、回访和失去兴趣是不同观察。一次接触不能建立长期偏好。

探索需要引用成功的工具结果，或助手回复中实际可见的充分创作内容。长期偏好至少需要 `interest.minEnduringTurns` 轮独立交流（默认 3）、一次探索和之后一次主动回访。用户明确点名的主题不能算作这次主动回访。负面经历可使兴趣暂不活跃；沉默、关闭程序和时间流逝不会。暂不活跃后，要重新形成长期偏好，须有新的探索和之后的回访。模型提出主题及归属化原因，生命核心检查当前轮引用和阶段条件。这些检查不能证明模型对对话的解释一定正确。

每次接受的变化都会持久保存前后阶段、原因和来源生命事件 ID。无变化评估也有持久的重放标记。不同 Session 的评估串行执行，重启恢复同一批兴趣。兴趣状态缺失或损坏时拒绝加载，不会静默替换生命。当前与历史阶段仍是模型推断，不是已核实的个人事实。

## 对话中的使用

下一次模型请求会通过已记录的 `genesis:self` 上下文接收少量活跃兴趣摘要；`genesis_self` 返回有界的当前摘要。助手可以在当前对话中提出相关研究或创作。实际工具调用仍须满足可用性及执行授权。兴趣不会启动后台任务，也不会虚构两次对话之间的活动。

“生命信息”展示当前兴趣、最近来源 ID 和有界变化历史。刷新读取最新状态；评估失败时保留之前的兴趣状态并报告安全诊断。`interest.windowTurns`、`interest.maxInterests`、`interest.minEnduringTurns` 和 `interest.contextChars` 是经过校验的部署限制。存储或响应容量不足会明确失败，不丢弃历史。

启用[审议](motivation.zh.md)后，兴趣还可从已记录自主决策的真实助手或工具结果形成；触发和行动计划本身不是经历。来源必须属于该决策的已结算结果。强度、稳定性和形成时间由既有证据派生，并随最新状态进入已记录的角色上下文。

## 限制

当前页面只读。主题匹配会拒绝大小写无关的完全重复名称，但不会自动合并语义近似的主题。主动回访由模型解释，并检查当前用户消息是否明确点名该主题；改写表达仍可能被误判。当前不提供自主唤醒或离线探索。
