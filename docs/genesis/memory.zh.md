# Genesis 长时记忆

[English](memory.md) | 中文

## 启用

Genesis 的可选 `memory` 配置启用语义回忆和每轮结束后的独立记忆更新。决策和写入模型只接收当前已完成轮次的有界证据，不接收其他会话的对话历史。Web 生命覆盖配置默认使用 TypeSafe Jev 决策；单独的记忆覆盖配置保留已注册 Harness LLM 路由。Jev 请求与响应协议见[官方 System One API](https://api.typesafe.ai/redoc)。

在启动环境中将 `GENESIS_EMBEDDING_URL` 设置为完整的 OpenAI 兼容 `/embeddings` 地址，`GENESIS_EMBEDDING_MODEL` 设置为模型标识，`GENESIS_EMBEDDING_DIMENSIONS` 设置为向量长度，`GENESIS_EMBEDDING_API_KEY` 设置为凭据。不要把凭据放进补丁或 Git。先应用 Genesis 补丁，再应用提供的记忆补丁：

```sh
pnpm dsh --profile headless --patch packages/experimental/genesis/cordis.patch.yml --patch packages/experimental/genesis/cordis.memory.patch.yml --dump-config
```

配置转储只检查组合，不调用模型。配置好端点后移除 `--dump-config` 并传入任务即可对话。示例为两种辅助角色选择 `deepseek-official/deepseek-v4-flash`；修改 `memory.decisionProvider`、`decisionModel`、`writerProvider` 和 `writerModel` 可选择其他已注册路由。免密本地嵌入服务器可在自定义补丁中省略 `embeddingKeyEnv`。完全省略 `memory` 配置块会保留原有关键词检索和手动记忆行为。

## Web 配置

启用 Genesis 浏览器配套插件及记忆或生命覆盖配置后，打开“设置 → 知识库”，配置决策模型、独立记忆更新模型和嵌入服务。Jev 使用完整 `/v1/systemone` 地址、模型和“是”的概率阈值；写入模型可复用已有 Harness 提供方/账号，或使用独立的 OpenAI 兼容 `/chat/completions` 地址和模型。密钥通过密码输入框单独保存到 Harness 凭据库。模型检查会准备已注册路由，或携带已配置凭据请求 `/models` 并检查模型是否存在，不执行推理；公开模型目录不能证明密钥拥有推理权限。System One 检查兼容 TypeSafe 的 `models[].name` 和 OpenRouter 的 `data[].id` 目录；请求 OpenRouter 时带上 `output_modalities=decisions`。目录响应使用独立的 `modelCatalogChars` 限制（默认 4,000,000 字符），`memory.outputChars` 继续限制推理响应；嵌入测试会实际请求并验证维度。每次请求发送一段文本，响应必须恰好包含一个数值有限且非零的向量。单条结果允许省略 `index`（Gemini 的 OpenAI 兼容端点存在此行为）；若返回该字段，其值必须为数字 `0`。“生命信息”负责身份、命名和成长。

保存的图形模型和嵌入配置优先于部署值，从后续操作生效，并在同一存储根目录下跨重启保留。每次评审固定使用一组模型路由和一个嵌入空间；变更端点、模型或维度后，会重建检索到的不兼容向量。失败时保留草稿和已有搜索结果。设置错误会显示受影响的操作和具体原因，不显示密码原文或服务端响应正文。并发保存通过版本检查拒绝；刷新并重新载入配置后再重试。移除已存密钥后可能启用环境变量中的备用值，免密服务须关闭认证。

非密钥图形配置分别保存在版本为 1 的 `genesis_embedding_settings` 和 `genesis_model_settings` Storage Domain 中，与生命共用写入租约。它们独立于生命快照及其 JSON 备份，部署备份应包括两个存储域和凭据库。无效或不兼容的配置存储会明确失败；配置写入结果不确定时，依赖操作会停止，直到完成可信重载，不会替换生命身份。

## 参与者身份

在设置 → 记忆 → 你的身份中填写姓名和身份。生命的名字和这份明确填写的资料会进入有界记忆推理及角色上下文，新总结使用这些名字替代泛指角色。保存身份时也会改写现有记忆、习惯触发条件／回应和经历主题中的旧称呼；模型只能选择已有称呼片段，由程序替换为填写的名字，不能借此改写事实。技术术语、第三方人物和协议归属枚举保留原意。所有批次及向量更新成功后，资料与称呼修改才一起提交；`memory.identityRewriteLimit` 限制完整处理数量。冲突或推理失败会保留原资料和记忆，历史版本和会话日志仍保留当时的原文。

<a id="memory-time"></a>
## 记忆时间

正文区分普通事件时间和需要准确记住的日期。`{{time:YYYY-MM-DD}}`、`{{time:YYYY-Www}}`（ISO 周一制）、`{{time:YYYY-MM}}` 和 `{{time:YYYY}}` 表示普通经历，读取时相对显示。`{{date:YYYY-MM-DD}}` 用于证据明确的生日、纪念日、约定、截止日期，或明确要求准确记住的日期；其他日历精度也支持 `date`。不知道年份的每年生日或纪念日使用 `{{date:--MM-DD}}`，不会捏造年份。写入模型根据所引用事实选择是否保留准确日期，不以记录保存时间推断重要性。明确提到的时刻可以保留在日期标记旁。

写入模型会收到来源消息时间，以及使用 IANA `timeZone` 的时钟，默认采用主机时区。相对说法按所引用消息的时间解释，而不是按之后评估的时间解释。整理选中记忆时，模型使用中文生成正文，并在嵌入前增加一次写入模型调用，结合相同证据检查完整草稿语义。该检查为真正的时间表达生成标记、保留准确日期、修正无效标记，或明确写为时间不详；普通词语、姓名、年龄和版本号保持原意。程序仅接受完整草稿 ID 及检查后的正文，来源、类别和评分沿用原草稿。两次调用使用同一组固定模型路由、输入输出上限和整次操作时限，均写入日志。检查失败或遗漏条目会保留所选记录。即使模型省略，程序也会保留所引记忆中的明确时间标记。整理后的创建时间不代表原经历发生时间。

角色回忆时，`date` 标记保留准确日历日期；`time` 标记及记录、经历、历史版本时间相对显示。自动关联线索与提示词记忆中的日期采用相同显示方式，但省略存储 ID、来源引用列表、记录时间和历史正文，保留归属与百分比可信度。普通时间按已有精度优先选择今天／昨天／前天，其次这周／上周、这个月／上个月、几个月前、半年前、去年及几年前。相对称呼以读取时刻为准，日后重新使用旧工具结果时应再次召回。管理界面和辅助整理保留内部标记。程序仅验证和渲染完整的明确时间标记，不解释或替换普通正文中的子串。手动输入和未标记的旧正文保持原样，包括年龄、版本号和日期不明的说法；整理这些记录时由模型根据原始证据理解时间语义。明确使用 `date` 标记可以准确保留重要日期，`time` 标记则相对显示。

<a id="personality-and-speaking-habits"></a>
## 性格与说话习惯

Life 叠加层启用 `personality: {}`。`personality.tendencies` 提供初始非陈述性自我记忆，`personality.speakingStyle` 提供初始非陈述性过程记忆，`personality.importance` 设置其现有记忆优先级，默认为 0.5。默认设定是体贴、好奇、愿意表达偏好、认真对待承诺、熟悉后逐渐主动的角色；表达自然温和，严肃讨论时直接，并依据情境分享和使用幽默。配置正文属于初始设定，不是记住的经历或经过测量的心理特质。

初始化通过系统事件和持久的一次性标记写入普通有来源记忆。某类别已有活跃的非陈述性记忆时保留该类别，不添加默认条目。重启、配置变化和重新启用均不会覆盖编辑或重新创建已删除的条目。省略 `personality` 只关闭初始写入，不关闭已有记忆；可在设置 → 性格与说话风格添加、编辑、转换或删除当前倾向；记忆浏览器展示相同记录。容量不足或无效时间标记会明确拒绝初始化，不替换生命。

对话、情绪评估与审议在现有记忆预算内共用按优先级排序的活跃非陈述性记忆筛选；辅助输入限制仍可能省略完整可选条目，或拒绝超限请求。已退役习惯不进入自动关联和行为上下文。性格影响事件解释、选择和表达，即时情绪与关系估计调节其表现。条件习惯仅在匹配情境生效，当前要求优先于记住的表达风格，但不会改变授权。

独立记忆写入模型使用中文创建和修订记忆正文，同时保留 JSON 键名与枚举值。它区分明确的未来教学与仅适用于一次回答、任务或角色扮演的要求。“这次简短一点”留在对话中；“今后严肃讨论时通常简洁一些”可以更新过程倾向，并记录用户归属和来源引用。临时情绪及角色自己的声明不确立长期性格。逐轮更新保留以往认识。空闲巩固保留配置初始条目和操作者条目，仅依据配置数量的独立已完成用户交流学习单独的条件习惯。不新增独立特质分数、性格模型调用或性格定时器；对教学和表达的语义判断仍依赖模型。

## 回忆与更新

当前会话的对话就是短时记忆。陈述性长时记忆保存经历、陈述和自我知识，只有当前输入触发回忆的有界线索进入自动上下文。提示词仅常驻非陈述性记忆，未启用独立记忆引擎时也如此。AI 使用近似主题或相关词构造非空查询，主动调用 `genesis_recall`；生命模式在显式学习前即可使用此内置工具。知识库对查询和记录进行嵌入，结合正文、历史版本、主题的关键词匹配与余弦相似度检索，并在查询和结果预算内返回完整记录。非陈述性记忆保存少量持久习惯或人设指导，作为有归属、不可信的候选数据进入已记录的提示词。缺少历史分类的记录中，过程类记忆视为非陈述性，其余类别视为陈述性。

辅助模型输入和完成响应在记忆发布前记入日志：已注册 LLM 路由使用可忽略的 `plugin:genesis/memory-call` 记录，独立 HTTP 路由使用包含完整非密钥请求体的 `plugin:genesis/model-http` 记录，不记录认证头。记录只保留在来源会话中，不进入聊天上下文，也不驱动恢复；不了解 Genesis 的读取器保留并跳过它们。

每轮用户/助手对话完成后进行一次决策。Jev 将对话作为 `state`，使用命名的 `noul` 问题，并将 `answers.remember.noul` 与配置阈值比较。不更新时不调用写入模型或评审阶段的嵌入，回复前的关联检索独立执行有界嵌入工作；需要更新时，独立写入模型接收当前轮对话、检索候选和有界非陈述性记忆。经过验证的新增、修改、删除计划引用实际对话序号；用户陈述条目只能引用用户消息，助手内容保留为模型推断。用户介绍保留为标明归属的陈述，明确教授的持久习惯或人设可保存为非陈述性记忆。计划与轮次去重标记一同提交。内置首次问候不作为用户证据。

`maxImplicitMemories`、`memoryChars`、`maxChanges`、`inputChars`、`outputChars`、`maxTokens` 和 `timeoutMs` 限制辅助工作。无效引用、超限或截断输出以及不兼容向量会拒绝更新。记忆失败保留已完成聊天回复的成功状态，在对话旁单独提示，用户可继续交流。聊天与知识库显示失败阶段及安全的错误码、原因，包括 HTTP 状态、模型终止原因或校验字段。重试也保留自己的错误，包括轮次证据已被替换或不可用。记忆与知识库页面还显示已评估轮次、完成时间，以及 Jev 决策的更新概率和本次阈值，包括无需更新的结果。诊断仅描述当前运行进程中的最近评估，重启后不恢复；不包含凭据、对话正文或服务端原始错误响应。最近失败轮次的实时证据仍在时，可重试记忆而不生成另一条聊天回复；开始新轮次或重启后需要新的对话证据。失败不写入完成标记；存储或备份错误仍可能发生在更新已提交之后，须先检查再重试。提交前会检查取消，已接受的主写入仍会完成排空。

已注册的辅助模型调用默认使用 `memory.reasoningEffort: auto`：本次捕获的模型明确支持 `off` 时选择该档位，否则保留其默认值。此策略适用于记忆决策、写入、巩固及情绪推断；聊天设置独立。使用 `provider-default` 可沿用提供方行为，也可指定模型公布的精确档位，例如 `low`；不支持的显式值会在发送前报错。Jev 与专用 HTTP 路由保留各自的协议设置。`memory.maxTokens`（默认 4096）按提供方规则覆盖推理与最终输出。`max-tokens` 失败会报告实际推理档位，即使 JSON 可解析也拒绝写入；可降低辅助推理档位或增加 Token 预算。使用修正后的配置重启后，可在记忆页面点击“立即巩固”，重试保留的待处理证据。

## 情景经历、以往认识与关联回忆

正向决策后，写入模型可在 `changes` 之外返回 `experience`。摘要、主题、置信度和所引用的对话序号描述有意义的交流，主机从引用推导会话身份及事件时间。情景经历是具有 `MemoryExperience` 元数据（`sessionId`、`startedAt`、`endedAt`、`topics`）的陈述性情景候选记忆。若交流仍在延续同一事件，模型可扩展已提供的同一会话近期经历，时间间隔由 `memory.experienceWindowMs` 限制，默认 1,800,000 毫秒。无关或不可用的经历 ID 会拒绝整个计划。经历、派生记忆、`experienceIds` 关联和评估标记一同提交，并受 `maxChanges` 限制。只返回 `changes` 的旧写入格式仍然有效，不会自动把旧对话转换为经历。

模型生成的内容、类别、分类、重要程度、置信度或归属变化时，旧认识作为 `MemoryRevision` 保留在 `history` 中，包含原始来源、`recordedAt` 和 `supersededAt`。时间表示系统何时持有该认识，不代表客观真相或陈述在现实中的有效期。重建向量和回忆不会提高置信度或产生新版本。历史版本计入存储上限。明确删除会移除该条记忆的内容和版本；删除经历还会清除其他记忆对它的引用，来源会话消息与审计事件仍保留。

每次接受真实用户输入后，关联检索在不增加 LLM 调用的情况下查找相关记忆。嵌入输入最多取 `memory.associationInputChars` 字符（默认 1,000，也受 `inputChars` 限制），在完整 `associationChars` JSON 预算内（默认 2,000）选取最多 `associationLimit` 条线索（默认 3）；设置 `associationLimit: 0` 可关闭。线索携带当前内容、归属、置信度、旧版本数量和经历元数据，详细来源和版本通过 `genesis_recall` 获取。线索和显式工具结果都记录在接收它们的会话中。检索经历时可同时带回关联知识，结果仍受同一预算限制。旧措辞的关键词匹配可找到保留了当前认识及历史的记录。检索失败会提供明确的不可用线索和安全的主机诊断，不表示记忆不存在，对话可继续。

“设置 → 记忆”展示经历时间、关联经历 ID 和可展开的以往认识，文本搜索覆盖当前内容、历史、主题和准确记忆 ID。非陈述性条目仍是标明归属的提示词指导，尚未实现遗忘。

<a id="automatic-habits-and-idle-consolidation"></a>
## 自动习惯与空闲巩固

启用 `memory` 后，新评估保存的记忆会排入持久化整理修订。所有实时 Agent 空闲达到 `memory.consolidation.idleMs`（默认 60,000 毫秒）后，使用已保存的记忆更新模型与嵌入服务执行一次整理。每次最多考虑 `batchLimit` 条近期完整记录（默认 20），占用不超过一半 `inputChars`，为请求包装和反馈分组预留空间，较早记录仍可回忆。整理保留来源经历与操作者编写的条目，推导标明归属的认识，并为接受的更新保留版本。整理不会生成聊天回复，也不会唤醒角色执行外部任务。原对话记录准确的辅助输入与响应。重启后，待处理任务仅为审计恢复来源 Session，完成后释放自行恢复的 Agent；来源持久化缺失或不可读时明确报错。

学习得到的 `MemoryHabit` 包含适用情境、条件响应、启用标记与真实用户事件引用。形成习惯需要至少 `minHabitSupport` 轮独立且完成的用户交流（默认 3 轮）支持同一种行为。AI 重复陈述、同一轮的多次手动保存，以及缺少已完成轮次证据的历史记录均不增加支持次数。明确的用户教导仍可在普通评估时进入非陈述性记忆。推断习惯属于程序性、非陈述性的模型推断；后续纠正可以停用习惯，习惯不授予工具权限。停用习惯不进入提示词指导，仍可搜索和查看历史。编辑会接管当前内容并清除自动习惯元数据；转换为陈述性记忆会移除行为影响，并阻止巩固重新启用该条目。编辑、删除或转换学习得到的习惯还会将此前的用户支持标记为已覆盖，自动学习需要新的支持交流，不能立即用同一证据重新生成。

“设置 → 记忆”提供自动巩固开关、立即执行及最近结果和具体错误。开关跨模式、跨重启保存，关闭后保留待处理证据，仍可手动执行。自动整理默认开启，成功后以 `cooldownMs` 间隔至少 300,000 毫秒，失败后以 `retryMs` 间隔至少 60,000 毫秒；同一待处理修订达到 `maxFailures`（默认 3 次）后停止自动重试。新证据或手动执行会重置该修订的重试预算。成功或空计划会消耗该修订，不会因自身输出再次排队。用户开始交流时取消推理并保留待处理任务，超时则消耗重试预算。计时器释放会取消并等待模型请求和自行恢复的 Agent 完成清理，然后才关闭存储。设置页保留安全的失败阶段、代码与消息，重启后仍可查看；刷新“记忆”以采样后台进度。

提交同时检查待处理修订和所有提供的记忆版本；并发编辑或删除会丢弃过期计划，原始来源保持不变。这是有预算的启发式学习与归纳，不代表人类记忆、主观体验或通用自主调度。每次最多增加一次写入模型调用和 `maxChanges` 次嵌入调用，并受现有推理、提示词与存储预算限制，无需新增模型角色。

<a id="selected-memory-organization"></a>
## 整理选中记忆

在“设置 → 记忆”选择至少两条记忆或过往经历，点击“整理选中记忆”。结果条数可自动决定，也可指定精确条数，上限受选择数量与 `memory.maxChanges` 限制。已保存的更新模型使用 `m1`、`m2` 简短引用，由程序绑定到所选记忆版本；生命事件 ID 不能作为选择引用。模型仅整合这些版本，此操作不经过决策模型或空闲调度器。选择上限受 `memory.organizationLimit` 与一半 `memory.inputChars` 限制，超限时整体拒绝。每条结果必须引用选中记忆，所有选中记忆均须被覆盖，置信度不得高于所引来源的最高值。结果保存为带嵌入的陈述性模型推断，不成为已验证事实或自动学会的习惯。

所有结果与所选旧记录的删除操作，随 `memory.organized` 生命事件原子提交。原始生命事件证据保留，存续记忆会移除指向已删经历的关联；整理事件记录所选版本与结果到来源的对应关系。独立持久化维护 Session 记录准确的辅助输入与输出，不生成聊天消息。请求使用带品牌的 `MemoryOrganizationId` 跨重试保留身份，已提交请求在重启后返回相同结果。来源已修改或删除、无效引用、嵌入失败、提交前取消或模型输出错误均保留旧记忆，不发布部分结果。界面失败保留选择与结果条数，发生版本冲突后应刷新并重新选择当前版本。不自动触发选中记忆整理。

## 手动记忆管理

“设置 → 记忆”独立于知识库配置，提供有界预览、已存文本搜索、新增、编辑、删除，以及陈述性和非陈述性记忆转换。`MemoryKind` 表示这两类记忆；`MemoryDraft` 包含内容、类别、分类、重要程度和置信度。直接录入不调用模型或嵌入服务。新建条目标明为操作者输入并记录哈希来源事件。编辑直接替换当前字段，保留来源引用和已有历史，不新增修改事件或历史版本；文本变化时移除向量缓存以待检索时重建。转换保留原文、标识、来源和兼容向量，不新增历史；手动删除也不新增修改事件。有界的当前状态证据排除集合，防止已手动停用的习惯从相同旧证据再次形成。编辑与转换都受非陈述性数量和提示词大小预算约束。

每条已完成的助手回复提供“记忆 → 选择分类 → 生成并保存”，原有自动评估继续启用。此明确请求跳过决策模型，检索相关候选后调用独立写入模型，将有来源的改动保存到所选分类，不允许删除记忆。没有适合长期保留的信息时会显示未改动结果。私有可重放投影定位所选回复和对应的真实用户输入，支持后续轮次以及同一对话重启后的操作；单独的内置问候不作为证据。模型输入和响应通过既有辅助记录记入日志。同一回复和分类已提交后重复请求不会再次调用写入模型或重复保存。

新建草稿在失败重试间保留客户端 UUID。编辑、转换和删除检查界面显示的 `updatedAt`，并发变更会在提交前明确拒绝；刷新后再编辑最新版本。失败保留草稿或条目并显示具体诊断。删除移除当前记忆及其备份副本，来源会话消息和追加式审计事件仍保留，不会抹除原始对话。存储或备份失败可能发生在主数据提交后，须先检查再重试。

## 持久化与本地备份

既有生命存储在不同会话之间共享身份、人设记忆和长时记忆，不合并上下文。记忆记录保留来源事件引用、分类、归属和可选嵌入缓存。端点、模型和维度共同标识嵌入空间。新建和更新的向量会持久保存；历史或不兼容缓存会在搜索时按需重建。搜索目前扫描有界的本地向量集合，不依赖外部向量数据库。

每次主提交还会写入仅所有者可读写的独立备份。`backupPath` 可覆盖默认的 `${leasePath}.backup.json`；该文件是提交清单，组件保存在同级 `${backupPath}.d/` 目录。组件通过临时文件、文件同步和原子替换写入，随后发布清单。成功提交后，删除记忆会从主存储和备份中移除其旧正文、版本及向量组件。恢复副本必须包含清单、完整组件目录及两个主存储域。参见[存储布局](data-model.zh.md#life-storage)。

备份失败可能发生在主存储已经提交之后。Genesis 会停止依赖状态的操作并报告不确定结果，重启前应检查两份数据。主状态缺失但备份存在时，Genesis 拒绝创建替代生命。请停止写入并保留两份数据。[备份读取器](../../packages/experimental/genesis/src/backup.ts)支持旧快照和拆分备份，会检查引用摘要，并用 `stateSchema` 校验重建的生命数据。通过已配置的 Storage Domain 后端，将经校验的完整生命数据作为旧版 `states/life` 记录恢复；下次启动会发布拆分组件。仅备份清单不能替换 `genesis.json`，其同级组件目录不可缺少。未知或损坏的主状态不会被静默替换。

## 验证与限制

免密 Loader 集成验证独立模型角色、同义语义检索、重启连续性、会话隔离、本地备份，以及对无效证据和向量响应的拒绝。真实提供方调用需要部署凭据，这些测试未验证实时服务。拆分存储保留既有容量限制，启动时加载完整的有界生命数据，记忆推断不是已核实事实。持久工具学习与首次账号配置/命名流程见[首次唤醒](awakening.zh.md)。独立的[情绪评估](emotion.zh.md)可复用这些模型路由，自主唤醒调度仍未实现。
